Enunciado

El TPI integra las capacidades principales de la materia en una solución defendible y reproducible.

Objetivo

Construir una solución integrada

El equipo debe resolver un caso de negocio mediante una API REST con persistencia, seguridad OAuth 2.0/JWT, scopes, asincronía, una integración adicional, observabilidad, pruebas y documentación técnica.

Modalidad

Trabajo grupal

Equipos de 3 a 5 integrantes, un repositorio por equipo, elección de dominio registrada con la cátedra, dos entregas principales y defensa técnica presencial.

API

Funcionalidad mínima

Al menos 3 entidades, 8 endpoints relevantes, CRUD de 2 entidades y una operación de negocio multi-paso que no sea solo ABM.

Integración

Asincronía + canal extra

Un flujo productor-consumidor o diferido con efecto visible, más una integración mediante Webhook, gRPC, WebSocket o equivalente aprobado.

Evidencia

Reproducibilidad

README completo, `.env.example`, datos iniciales, pruebas, observabilidad, tag/release, hash de commit y demo final.

Entregas

Dos hitos grupales con foco incremental.

Seguridad requerida

La API debe validar identidad, permisos y configuración antes de ejecutar acciones sensibles.

Authorization Server

Auth0 o equivalente

Configurar API, audience, issuer, scopes y un cliente Machine to Machine.

OAuth 2.0

client_credentials

Obtener access token desde el cliente y enviarlo como Bearer token a la API.

Resource Server

Validación JWT

Verificar firma, issuer, audience, expiración y scopes requeridos por endpoint.

Dominios ordenados

Cada equipo elige un dominio y lo registra con la cátedra para evitar repeticiones.

Ver detalle completo
Dominio

1. Pedidos en restaurante

  • CRUD: productos y pedidos.
  • Flujo: confirmar pedido, calcular total, cambiar estado y generar orden de cocina.
  • Integración: WebSocket de cocina, Webhook de estado o gRPC a stock.
  • Scopes: `read:pedidos`, `write:pedidos`, `confirm:pedidos`, `admin:productos`.
Dominio

2. E-commerce

  • CRUD: productos y pedidos o carritos.
  • Flujo: confirmar compra con stock, total, pedido y pago simulado.
  • Integración: Webhook de pago, gRPC a stock o WebSocket de estado.
  • Scopes: `read:productos`, `write:productos`, `write:pedidos`, `confirm:compras`.
Dominio

3. Turnos de salud

  • CRUD: pacientes y turnos o profesionales.
  • Flujo: reservar turno validando disponibilidad y evitando solapamientos.
  • Integración: Webhook de confirmación, WebSocket de agenda o historia clínica simulada.
  • Scopes: `read:turnos`, `write:turnos`, `cancel:turnos`, `admin:profesionales`.
Dominio

4. Mesa de ayuda

  • CRUD: tickets y usuarios o agentes.
  • Flujo: escalar ticket validando prioridad, estado, responsable y SLA.
  • Integración: Webhook a canal externo, WebSocket de tablero o gRPC a usuarios.
  • Scopes: `read:tickets`, `write:tickets`, `assign:tickets`, `close:tickets`.
Dominio

5. Biblioteca digital

  • CRUD: títulos y usuarios o préstamos.
  • Flujo: prestar e-book validando cupo, usuario, vencimiento y espera.
  • Integración: WebSocket de lista de espera, Webhook a mailing o gRPC a catálogo.
  • Scopes: `read:titulos`, `write:titulos`, `read:prestamos`, `write:prestamos`.
Dominio

6. Eventos y entradas

  • CRUD: eventos y entradas o compras.
  • Flujo: comprar entrada validando disponibilidad, pago y emisión.
  • Integración: Webhook de pago, WebSocket de control de acceso o gRPC a validador.
  • Scopes: `read:eventos`, `write:eventos`, `buy:entradas`, `validate:entradas`.
Dominio

7. Alquiler de vehículos

  • CRUD: vehículos y reservas.
  • Flujo: confirmar reserva con disponibilidad, bloqueo, verificación y contrato.
  • Integración: gRPC a inventario, Webhook de reserva o WebSocket de disponibilidad.
  • Scopes: `read:vehiculos`, `write:vehiculos`, `read:reservas`, `confirm:reservas`.
Dominio

8. Salas de co-working

  • CRUD: salas y reservas.
  • Flujo: programar reserva validando disponibilidad, capacidad y recursos.
  • Integración: Webhook con calendario, WebSocket de ocupación o gRPC a recursos.
  • Scopes: `read:salas`, `write:salas`, `read:reservas`, `admin:recursos`.

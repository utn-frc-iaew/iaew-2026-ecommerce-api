Negocio

Confirmar pedido

  • Buscar pedido.
  • Validar estado `pendiente`.
  • Validar stock.
  • Descontar stock.
  • Guardar `estado: confirmado`.
  • Si ya estaba confirmado: `409 Conflict`.

Concepto clave

Idempotencia: qué significa

Significado

Ejecutar la misma operación una o varias veces deja el sistema en el mismo estado esperado.

Qué evita

Doble click, reintentos por timeout, cobros duplicados, stock descontado dos veces o pedidos confirmados dos veces.

En esta API

Confirmar un pedido ya confirmado no vuelve a descontar stock: responde `409 Conflict`.

La clave no es solo devolver un error: es evitar repetir el efecto de negocio.

Código defensivo

Evitar doble confirmación

app.post('/pedidos/:id/confirmar', async (req, res) => {
  const pedido = await Pedido.findById(req.params.id);

  if (!pedido) {
    return res.status(404).json({ error: 'Pedido no encontrado' });
  }

  if (pedido.estado !== 'pendiente') {
    return res.status(409).json({
      error: 'El pedido ya fue confirmado'
    });
  }

  pedido.estado = 'confirmado';
  pedido.confirmadoEn = new Date();
  await pedido.save();

  res.json(pedido);
});
Estado esperado: solo `pendiente` puede pasar a `confirmado`.
  • `404`: el recurso no existe.
  • `409`: la acción choca con el estado actual.
  • La segunda confirmación no ejecuta el descuento de stock.

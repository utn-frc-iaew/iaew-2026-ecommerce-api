Concepto base

Autenticación no es autorización

Autenticación

¿Quién sos?

Validar una credencial: token, sesión, certificado, API key o identidad federada.

Autorización

¿Qué podés hacer?

Decidir si esa identidad puede ejecutar una acción concreta sobre un recurso.

Primero identidad, después permiso.05 / 20

Auth0

Un Authorization Server como servicio

Qué aporta
  • Emisión de tokens OAuth 2.0.
  • Firma de JWT con claves administradas.
  • Definición de APIs, audience y scopes.
  • Clientes Machine to Machine.
Qué no delegamos
  • Diseñar permisos del dominio.
  • Validar scopes en cada endpoint.
  • Proteger secretos y configuración.
  • Responder bien ante errores.
Auth0 resuelve identidad y emisión; la API sigue decidiendo.06 / 20

JWT

Qué valida la API

Token válido
  • Firma correcta contra JWKS.
  • issuer esperado.
  • audience de nuestra API.
  • Token no expirado.
Permiso suficiente
  • La acción pide un scope.
  • El token trae ese scope.
  • Si falta: 403 Forbidden.
  • Si no hay token válido: 401 Unauthorized.
Autenticación valida identidad; autorización valida alcance.11 / 20

Headers

OAuth 2.0 y API key en HTTP

Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
x-api-key: clave-interna-demo
Bearer JWT

Access token emitido por Auth0. La API valida firma, issuer, audience, expiración y scopes.

API key

Clave compartida para una integración simple. Es fácil de probar, pero menos expresiva que OAuth 2.0.

Ambas son credenciales; no expresan lo mismo.13 / 20
